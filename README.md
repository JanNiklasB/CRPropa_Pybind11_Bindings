# CRPropa Pybind11 Bindings Plugin

This plugin compiles CRPropa with pybind11 bindings instead of swig bindings.
For that it either clones a given git repository over fetch content or uses a local repository over `CRPROPA_SOURCE` and builds it from source, it is compatible with any CRPropa version that has merges https://github.com/JanNiklasB/CRPropa3/tree/pybind11PluginAdjustments .
It is not possible to use a preinstalled CRPropa without the source code, since to be able to automatically build the binding files with binder we need the `compile_commands.json`, the `CMakeCache.txt` generated by CRPropa and the source files.

## Install requirements

You need the install-requirements of [CRPropa](https://github.com/CRPropa/CRPropa3/blob/master/doc/pages/Installation.md#conda) (you do not need swig) plus the following requirements:

```bash
conda install -c conda-forge janniklasb::binder pyvind11 ninja pybind11-stubgen
```

## How to build CRPropa with this plugin

The building process is straight forward, clone the repository, install the requirements, specify the variables, build, install, done.

```bash
git clone https://github.com/JanNiklasB/CRPropa_Pybind11_Bindings.git
cd CRPropa_Pybind11_Bindings

mkdir build && cd build
cmake .. -G Ninja -D CMAKE_INSTALL_PREFIX=/path/to/your/desired/install/location
# by default the current master (for now a slightly modified version to enable some features) is pulled per fetch content, but you are also able to specify your own repo and tag or local CRPropa source
cmake --build .
# installing overwrites the existing crpropa!
cmake --install .
```

### CMake Variables

- `CRPROPA_SOURCE` : Path to a local repository of CRPropa, if set disables fetch content option
- `CRPROPA_GIT_REPOSITORY` : URL to git repository
- `CRPROPA_GIT_TAG` : Git tag to check out to, can be a branch, tag or commit hash

# CMake Binder Tool

To use the custom underlying `binder` cmake tool that is installed with this custom `binder` conda package you first need to include it in you cmake project:

```cmake
find_package(cppbinder)
```

You can then generate the bindings file with the `cppbinder_add_target`:

```cmake
cppbinder_add_target(<name>
	[BINARYFOLDER <directory>]
	ROOTMODULE <modulename>
	[OUTPUTFOLDER <directory>]
	CONFIGFILE <file>
	PROJECTLIB <file|target>
	[PROJECTINCLUDES <file>...]
	[PROJECTEXTRASOURCES <file>...]
	HEADERS	<file>...			
)
```

You also need to create a config file for you project, you can check out our [`binder.cfg`](/python/binder.cfg) for an example and/or look into the [binder documentation](https://cppbinder.readthedocs.io/en/latest/config.html#config-file-options).

## Function Arguments

- `BINARYFOLDER`:
	Binary folder to use for subproject, defaults to `${CMAKE_CURRENT_BINARY_PATH}/bindings-bld`

- `ROOTMODULE`:
	The name of the rootmodule, same as binder `--root-module ${ROOTMODULE}`

- `OUTPUTFOLDER`:
	Specify a directory where the compiled bindings file will be placed.
	Default is `${CMAKE_CURRENT_BINARY_DIR}/${name}`

- `CONFIGFILE`:
	The configfile to use, same as binder `--config ${CONFIGFILE}`

- `PROJECTLIB`:
	The library file|target to link to the generated binary, the target will be dependend on that file|target

- `PROJECTINCLUDES`:
	List of includes to add the generated pybind target, should be at least the ones used for `PROJECTLIB`

- `PROJECTEXTRASOURCES`:
	Additional source files to be handed over to the pybind target in addition to the ones generated by binder	

- `HEADERS`:
	List of headers from which the includes will be extracted and used to generate the bindings.
	To compare the resulted inputs check `${BINARYFOLDER}/includes_for_bindings.h`
